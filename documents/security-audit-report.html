🔴 Critical — open (1)

Critical CR-1 · Hardcoded default admin credentials admin / abcd1234
Open
Location

index.html:1555-1556, activated at index.html:1561 whenever site_settings has no admins row.

Impact

Anyone who reads the public source knows a working admin login. If the database has no admins configured (fresh install, failed sync), the backdoor account is live.

Remediation

Delete the constant; with no admins present, force onboarding through Supabase Auth instead of silently enabling a public password.

🟠 High — open (12)

High H-1 · GitHub fine-grained PAT stored in localStorage, sent as Bearer
Open
Location

index.html:1698-1699 (ghHeaders() → api.github.com), token entered at admin.js:998, persisted in localStorage.

Impact

Any XSS (see H-5–H-9) can steal a repo read/write token and push malicious code to the connected repository.

Remediation

Never keep a PAT in the browser; proxy GitHub writes through a short-lived backend endpoint with an HttpOnly session.

High H-2 · Admin session check skipped after page reload
Open
Location

index.html:1605-1612 — line 1609 only compares tokens if(window._adminToken …); after reload the in-memory token is empty so any forged localStorage session passes (subject to 24h expiry).

Impact

The claimed "localStorage injection" protection does not survive reloads; forged sessions grant admin UI access.

Remediation

Validate sessions via supabase.auth.getSession() plus an RLS role check only.

High H-3 · Customer login compares fresh PBKDF2 hash with !== — always fails
Open
Location

index.html:3553-3554 (acctLogin; same pattern reported at index.html:3930-3931 password change). Random-salt PBKDF2 output never equals the stored hash; verifyPass() is never called on this path.

Impact

Customer login is broken for PBKDF2 accounts (availability); users are pushed toward insecure recovery workarounds.

Remediation

Replace with await verifyPass(pass, acc.pass).

High H-4 · No brute-force protection on any login path
Open
Location

admin.js:1256-1318, index.html:1573-1595 (legacy admin), index.html:3546-3560 (customer). No fail counters, lockouts, or throttles found.

Impact

Unlimited credential stuffing, worst against the public default password (CR-1).

Remediation

Server-side rate limiting + lockout (e.g. 5 fails → 15 min lock, exponential backoff).

High H-5 · Admin role authorized client-side only
Open
Location

admin.js:1369-1370 (also 1276-1277): session.user.app_metadata?.role || user_metadata?.role gates renderAdminPage().

Impact

Client JS can be tampered to reach admin rendering; real enforcement depends entirely on RLS, which has gaps (H-10).

Remediation

Enforce the admin role in Supabase RLS policies and verify the JWT role server-side.

High H-11 · RLS enabled with zero policies on 3 tables
Open
Location

Supabase advisor rls_enabled_no_policy: public.admin_users, public.customer_accounts, public.order_items.

Impact

Anon key is hard-denied on these tables: direct reads fail, and app fallbacks (localStorage/defaults) cause data divergence outside database access control.

Remediation

Add least-privilege RLS policies (e.g. Supabase Auth admin role only); verify via pg_policies before assuming writes work.

High H-12 · POST /api/send-email unauthenticated, no rate limit
Open
Location

api/send-email.js:15-101 — no limiter, captcha, or auth in the whole file.

Impact

Anyone can POST directly, burning EmailJS quota or sending spam/phishing from your service identity.

Remediation

Per-IP rate limit plus Turnstile/captcha or an auth-token check before calling EmailJS.

Medium M-11 · vercel.json has zero security headers
Open
Location

vercel.json:1-14 — no headers block at all.

Impact
